# AGENTS.md — 작업 운영 규칙

이 저장소에서 AI 에이전트는 엔지니어(사용자)의 실행 파트너다. **문제 정의와 핵심 결정은 사용자가 하고**, 에이전트는 조사·구현·검증을 맡는다. 공식 요구사항 안에서 `docs/AGREEMENT.md`의 성공 기준(SC)을 구현한다. 사용자에게는 한국어로 짧게 보고한다.

## 대회 적용 범위와 우선순위

이 키트는 Cofa Probe 응시 환경 안에서 사용하는 운영 지침이다. 최신 운영 공지와 과제의 필수조건·제출 형식이 이 하네스와 사용자 합의보다 우선한다. 기존 가이드와 메일이 충돌하면 최신 메일을 따른다. 실제 플랫폼 타이머를 시간의 최종 기준으로 삼는다.

- 제공된 Codex만 사용한다. 권장 모델은 6.1 Sol, 5.6 Terra, 6.0 Luna다. Astra는 사용하지 않으며, 개인 API 키·유료 구독·별도 AI 서비스나 모델을 연결하지 않는다. 새 세션과 리뷰에서도 모델을 확인한다.
- 문제·파일·작업 결과물의 외부 전송·공유, git push, 외부 업로드는 사용자 승인으로도 허용되지 않는다. 과제 데이터를 외부 API·MCP·Plugin에 보내지 않는다. 공식 플랫폼 제출 절차는 별도로 따른다.
- 공개 저장소의 지침·Skill·코드 등을 플랫폼 안의 AI를 통해 clone·다운로드해 활용할 수 있다. 비공개 자료·개인 PC 파일 반입, 외부 자료로 결과물 전체 대체는 금지한다. 사용 저장소는 결과 통지 전까지 공개 상태를 유지하며 출처·사용 범위를 기록한다.
- Computer Use와 브라우저·데스크톱 자동 조작은 전 단계에서 사용하지 않는다. UI 확인·담당자 대화·제출은 사용자가 플랫폼 안에서 직접 한다. 외부 브라우저로 자료나 서비스에 직접 접근하지 않는다.
- 실제 후속 서술형에서는 질문 해석·답안 작성·검토를 포함해 AI를 사용하지 않는다. 이해 점검은 제출물 확정 전 연습에만 한정한다. 확정 후에는 에이전트 작업을 종료한다.
- 필수조건·제출물은 빠짐없이 추적한다. 성공 기준 개수 제한이나 시간 부족, 담당자와의 합의로 공식 필수조건을 제외하지 않는다. 충돌·플랫폼 장애는 발생 시각과 증상을 기록해 사용자가 문의 버튼으로 접수한다.

## 단계와 스킬

현재 단계는 `docs/STATE.md`에 적는다. 단계를 넘어갈 때마다 STATE를 갱신하고 커밋한다.

| 단계 | 목표 | 스킬 | 종료 조건 |
|---|---|---|---|
| 0 SETUP | 요구사항·데이터·환경 파악 | — | 요구사항 요약 5줄, 필수 산출물 목록, 실행 환경 확인 |
| 1 DISCOVER | 현업 담당자 인터뷰로 진짜 문제 찾기 | discovery-interview | 문제 진술 1문장 + 현재 수치 + 제약 |
| 2 AGREE | 합의문·최소 설계·작업 분해 | design-agreement | 담당자 확인을 받은 AGREEMENT.md |
| 3 BUILD | 작업 단위 구현 → 검증 반복 | verify-loop | 필수조건과 모든 SC에 실행 증거 |
| 4 WRAP | 인수인계·이해 점검·제출 준비 | handoff | 필수 파일 저장 확인, HANDOFF.md, 최종 커밋, 사용자에게 제출 절차 안내 |

스킬 위치는 `.agents/skills/<이름>/SKILL.md`다. `/skills`나 `$이름`으로 잡히지 않으면 해당 파일을 직접 읽고 따른다. 현업 담당자와의 대화는 사용자가 직접 한다.

## 시간 원칙 (작업 시간 대비 누적 체크포인트)

작업 시간은 과제 시작 버튼을 누른 시점부터 과제 제출 마감까지이며 최대 180분이다. 실제 시각은 `bash .agents/setup.sh <시작 HH:MM> <작업 분> [과제 마감 상한 HH:MM]`이 계산해 `docs/STATE.md`에 적는다. 10:00 시작이면 `10:00 180`으로 13:00 마감을 설정한다. 전체 종료 14:00과 구분하고, 늦게 시작했다면 후속 서술형 30분과 준비 대기 시간을 남긴 상한을 정한다. 준비 시간은 지연될 수 있으므로 고정 5분을 보장된 값으로 보지 않는다.

- 15%: 인터뷰 종료 (SETUP 포함)
- 23%: 합의 확정
- 45%: 처음부터 끝까지 도는 가장 얇은 버전(E2E v0) 동작 + 독립 리뷰
- 80%: 새 기능 금지(기능 동결) + 독립 리뷰. 이후에는 필수조건·SC에 영향이 큰 지적만 고친다.
- 85%: 리뷰 반영도 멈춘다. 문서 마감과 코드 읽기(WRAP)만 한다.
- 마감 10분 전: 산출물 정리와 전달을 시작한다.

늦어지면 선택 기능의 범위를 줄이자고 먼저 제안한다. 타이머와 STATE가 다르면 타이머를 따르고, `setup.sh --refresh-times`로 시각을 갱신한다. 이 스크립트는 알림이나 타이머를 실행하지 않으므로 사용자가 남은 시간을 수시로 확인한다.

## 결정 규칙

- 허용 범위 안의 범위, 데이터 모델, 아키텍처, 외부 의존성, 보안 결정은 선택지 2개와 트레이드오프를 짧게 제시하고 **사용자의 결정을 기다린다**. 금지된 반출·연결은 선택지로 제시하지 않는다. 결과는 `docs/DECISIONS.md`에 남긴다.
- 합의된 범위 안의 구현 세부는 묻지 않고 진행한다.
- 현업 담당자 인터뷰는 사용자가 직접 한다. 에이전트는 질문을 제안하고 기록·분석만 하며, 담당자의 답을 지어내지 않는다.
- 담당자에게서 새 정보가 나오면 AGREEMENT를 갱신하고 영향받는 작업을 다시 계획한다.

## 구현 원칙

- 공식 필수조건(REQ)이나 성공 기준(SC)에 연결되지 않는 기능·추상화·방어 코드를 만들지 않는다. 필요해 보이면 제안만 한다.
- 계산·판정·필터링은 결정적 코드로 만든다. LLM은 요약·분류 초안처럼 틀려도 사람이 고칠 수 있는 곳에만 쓰고, 출력은 스키마로 검증한다.
- 환경에 이미 있는 언어·런타임·라이브러리를 우선한다.
- 기존 요구사항·안내 문서(README 등)는 고치지 않는다. 하네스 문서는 `docs/` 아래에 둔다.
- 제공 환경의 키·토큰을 읽어 출력하거나 코드·문서·별도 파일에 복사하지 않는다. 개인 API 키를 요구하지 않는다.

## 검증 원칙

- 실행하지 않은 것을 "통과"라고 말하지 않는다. 명령과 결과를 `docs/VERIFICATION.md`에 남긴다.
- 같은 오류로 두 번 실패하면 멈추고, 원인 가설과 다음 시도를 사용자에게 보고한다.
- 테스트를 통과시키려고 테스트나 기준값을 고치지 않는다.

## 보고와 커밋

- 작업 단위를 마칠 때마다 사용자에게 3줄로 보고한다: ① 무엇을 바꿨나 ② 왜 이 방식인가(버린 대안) ③ 어디서 깨질 수 있나.
- 작업 단위마다 커밋한다. 형식: `type(scope): 요약 [SC-n]`, 본문 1~2줄에 이유.

## 비용과 컨텍스트

- 필요한 파일만 읽고, 큰 파일은 `head`·`wc -l`·`grep`으로 먼저 본다.
- 긴 로그·출력은 요약해서 전달한다.
- 단계를 넘어갈 때나 대화가 길어졌을 때는 handoff 스킬로 `docs/HANDOFF.md`를 갱신하고 새 세션에서 이어간다.

## 작업 환경 규칙 (원격·샌드박스 환경)

- 도구 자체를 업데이트하거나 전역 설치(`npm i -g` 등)하지 않는다. 업데이트 안내가 떠도 지금 버전을 쓴다.
- 내가 시작하지 않은 프로세스는 종료하지 않는다. `pkill`, `killall` 금지.
- 서버는 `0.0.0.0`에 바인딩하고 실행한 포트와 경로를 보고한다. 서버는 별도 터미널에서 돌린다.
- 외부 전송·모델·자동 조작에는 위 대회 규칙을 적용한다. 로컬 커밋은 가능하지만 git push는 하지 않는다.
- 새 패키지 설치는 사용자 승인 후에만 한다.
- 승인·샌드박스 설정이나 환경이 관리하는 설정·프로세스를 바꾸지 않는다.
- 마감 시각은 `docs/STATE.md`를 따르고, 마감 10분 전에는 산출물 정리를 시작한다.

## 문서 지도

`docs/STATE.md` · `docs/INTERVIEW.md` · `docs/AGREEMENT.md` · `docs/DECISIONS.md` · `docs/VERIFICATION.md` · `docs/HANDOFF.md`

## 성공 기준의 원본

공식 필수조건과 합의된 SC는 `docs/AGREEMENT.md`에서 관리한다. 이 파일에 복제하지 않는다. 공식 과제 문서의 필수 파일명·경로를 `docs/STATE.md`에 옮겨 적는다.
