# 1장 요약

열기: 에디터 파일 검색(⌘P / Ctrl+P)에서 `CHEATSHEET`, 또는 `cat .agents/CHEATSHEET.md`

## 시간 (작업 시간 대비)

| 15% | 23% | 45% | 80% | 85% | 마감 10분 전 |
|---|---|---|---|---|---|
| 인터뷰 끝 | 합의 확정 | E2E v0 | 새 기능 금지 | 리뷰 반영 중단 | 마감 준비 |

실제 시각은 `setup.sh`가 `docs/STATE.md`에 적는다. 늦어지면 SC 개수를 줄이고, 검증과 문서는 지킨다.

## 인터뷰 사다리 — "맥사우수 관제성확"

맥락 → 최근 사례 → 우회 방법 → 수치(출처까지) → 관계자 → 제약 → 성공의 모습 → 되읽기 확인

- 질문은 내 말로 직접 쓴다. 해결책 이야기는 문제를 다 들은 뒤에.
- 지름길 질문("할 일 정리해 주세요")은 하지 않는다. 사소한 질문부터 맥락을 쌓는다.
- 숫자는 출처를 묻고 데이터와 대조한다.
- 답은 `docs/INTERVIEW.md`에 모아 붙이고, 분석은 2~3개씩 묶어서 맡긴다.

## 합의문 7칸

문제 진술 · 원인 · 성공 기준 3개 이하(지표 / 현재 / 목표 / 측정) · 만들 것 · 만들지 않을 것 2개 이상 · 제약 · 데모 시나리오

→ 5줄 확인 메시지 → 정정 반영 → 변경 이력에 기록

## 검증 7단계

완료 조건 → 자동 검사 → 실제 실행(브라우저 미리보기·curl, 골든 테스트) → 경계 사례 2개 → 추적표 → 범위 점검(`git diff --stat`) → 3줄 보고와 커밋

기준 수치와 다르면 코드를 맞추지 말고 차이를 규칙별로 분해한다. AI가 틀린 지점은 DECISIONS.md에 한 줄씩 남긴다.

## 인수인계 7칸

한 줄 요약 · 현재 상태 · 실행 방법 · 구조 · 핵심 결정 · 위험과 대응 · 다음 세션 첫 지시문

## 확인 질문 답변 틀 (AI 없이 직접)

읽기 → 쓰기 → 사실 확인. 전제가 실제와 다르면 먼저 바로잡는다: "질문은 ~라고 했지만 실제로는 ~"

① 결론 → ② 위치(파일 · 함수 · 결정) → ③ 근거(버린 대안, 숫자) → ④ 파급과 위험 → ⑤ 다음 조치

## 명령이 안 될 때

- `/skills`·`$이름`이 안 되면: "AGENTS.md와 .agents/skills/<이름>/SKILL.md를 읽고 따라"
- `/new`가 없으면 Codex를 종료했다가 다시 연다.
- `/review`가 없거나 비면 새 세션에 `.agents/skills/verify-loop/references/review-prompt.md`를 준다.

## clone이 안 될 때 — 부트스트랩 프롬프트

시작하자마자 에이전트에게 입력한다.

```

```
