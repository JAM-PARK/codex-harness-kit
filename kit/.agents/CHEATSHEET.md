# 1장 요약

열기: 에디터 파일 검색(⌘P / Ctrl+P)에서 `CHEATSHEET`, 또는 `cat .agents/CHEATSHEET.md`

## 대회 경계

- 최신 운영 공지·공식 필수조건이 하네스·사용자 합의보다 우선한다.
- 제공 Codex에서 6.1 Sol만 사용한다. 사용자 선호로 Terra·Luna 제외. Astra·개인 API 키·별도 AI 연결·Codex 업데이트 금지.
- 문제·파일·결과물 외부 전송·공유·push 금지. 공개 자료의 clone·다운로드만 허용 범위에서 활용하고 출처를 남긴다. 사용 저장소는 결과 통지 전까지 공개 유지.
- Computer Use·브라우저 자동 조작 금지. 사용자가 플랫폼 Browser에서 직접 UI를 확인하고, Codex는 로컬 CLI 검증을 맡는다.
- 실제 후속 서술형에서는 AI·복사 붙여넣기 금지. 제출물 확정 후 AI 작업을 종료한다.

## 시간 (작업 시간 대비)

| 15% | 23% | 45% | 80% | 85% | 마감 10분 전 |
|---|---|---|---|---|---|
| 인터뷰 끝 | 합의 확정 | E2E v0 | 새 기능 금지 | 리뷰 반영 중단 | 마감 준비 |

실제 시각은 `setup.sh`가 `docs/STATE.md`에 적는다. 10:00 과제 시작이면 `bash .agents/setup.sh 10:00 180` → 13:00 과제 마감, 12:50 제출 준비다. 전체 종료 14:00과 혼동하지 않는다. 늦게 시작했다면 서술형 30분·준비 대기를 남긴 과제 마감 상한을 지정한다. 플랫폼 타이머가 우선이며 자동 알림은 없다. 일정 수정은 `setup.sh --refresh-times`로 시각만 갱신한다. 늦어지면 선택 기능을 줄이며 공식 필수조건은 제외하지 않는다.

## 모델·effort (모두 6.1 Sol)

| 작업 | 권장 effort |
|---|---|
| SETUP · DISCOVER | medium |
| AGREE 핵심 결정·최소 설계 | high |
| BUILD 상세 설계 | high, 재작업 위험이 큰 미해결 결정만 xhigh |
| BUILD 구현·디버깅·검증 설계·독립 리뷰 | high |
| WRAP 코드 이해·심화 문답·피드백 | high |
| 확정 내용 정리·단순 반복 수정·기존 검사 실행과 기록·제출 체크 | medium |

AGREE 설계를 BUILD에서 반복하지 않는다. xhigh는 핵심 쟁점 검토 뒤 high로 복귀한다. 단계 전환 때 실제 모델·effort를 지원 UI에서 확인하고 STATE에 기록한다. 자동 전환이 아니다. 상세 기준은 AGENTS.md 참조.

## 인터뷰 사다리 — "맥사우수 관제성확"

맥락 → 최근 사례 → 우회 방법 → 수치(출처까지) → 관계자 → 제약 → 성공의 모습 → 되읽기 확인

- 질문은 내 말로 직접 쓴다. 해결책 이야기는 문제를 다 들은 뒤에.
- 지름길 질문("할 일 정리해 주세요")은 하지 않는다. 사소한 질문부터 맥락을 쌓는다.
- 숫자는 출처를 묻고 데이터와 대조한다.
- 답은 `docs/INTERVIEW.md`에 모아 붙이고, 분석은 2~3개씩 묶어서 맡긴다.

## 합의문 7칸

공식 필수조건·제출 파일명은 개수 제한 없이 추적한다. 추가 SC는 3개 이내 권장이다.

문제 진술 · 원인 · 성공 기준(지표 / 현재 / 목표 / 측정) · 만들 것 · 제외할 선택 기능 · 제약 · 데모 시나리오

→ 5줄 확인 메시지 → 정정 반영 → 변경 이력에 기록

## 검증 7단계

완료 조건 → 자동 검사 → 실제 실행(사용자 수동 미리보기 / Codex의 로컬 curl·골든 테스트) → 경계 사례 2개 → 필수조건·SC 추적표 → 범위 점검(`git diff --stat`) → 3줄 보고와 로컬 커밋

기준 수치와 다르면 코드를 맞추지 말고 차이를 규칙별로 분해한다. AI가 틀린 지점은 DECISIONS.md에 한 줄씩 남긴다.

## 인수인계 7칸

한 줄 요약 · 현재 상태 · 실행 방법 · 구조 · 핵심 결정 · 위험과 대응 · 다음 세션 첫 지시문

## 확인 질문 답변 틀 (AI 없이 직접)

AI의 연습·피드백은 제출물 확정 전까지만 한다. 실제 서술형 문항을 AI에 가져오지 않는다.

WRAP 기본 산출물: `docs/SELF_QUIZ.md`에 최대 6개의 **심화 질문 + 모범답안 + 코드 근거 + 꼬리질문과 답안 요점**. 설계·의사결정·데이터 모델을 우선하고 트랜잭션·동시성·쿼리 성능·전제 오류를 실제 구현에 맞춰 다룬다. 답변을 기다리지 않고 문답 자료부터 완성하며, 시간이 부족하면 질문 수를 줄이고 답안은 유지한다. 한 문제씩 풀기는 선택이다.

읽기 → 쓰기 → 사실 확인. 전제가 실제와 다르면 먼저 바로잡는다: "질문은 ~라고 했지만 실제로는 ~"

① 결론 → ② 위치(파일 · 함수 · 결정) → ③ 근거(버린 대안, 숫자) → ④ 파급과 위험 → ⑤ 다음 조치

## 사용자 수동 제출

필수 파일·에디터 저장 상태 확인 → '제출하고 문제풀기' 미리보기 → '제출물 확정하고 문제풀기' → AI 작업 종료 → 문항 준비 후 직접 서술형 시작·답변 → 완료 화면의 제출 ID·시각·파일 수·크기 확인. 미리보기 중에도 시간은 흐른다. 로컬 커밋은 제출 완료가 아니며, 감독 연결은 완료 안내까지 유지한다.

## 명령이 안 될 때

- `/skills`·`$이름`이 안 되면: "AGENTS.md와 .agents/skills/<이름>/SKILL.md를 읽고 따라"
- `/new`가 없으면 Codex를 종료했다가 다시 연다.
- `/review`가 없거나 비거나 모델·effort를 확인할 수 없으면 제공 Codex의 새 세션에서 6.1 Sol / high를 확인하고 `.agents/skills/verify-loop/references/review-prompt.md`를 준다.

## clone이 안 될 때 — 부트스트랩 프롬프트
