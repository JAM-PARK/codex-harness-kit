# 1장 요약

열기: 에디터 파일 검색(⌘P / Ctrl+P)에서 `CHEATSHEET`, 또는 `cat .agents/CHEATSHEET.md`

## 작업 원칙

- 기존 프로젝트 지침·보안 정책과 사용자 요구사항을 확인하고 충돌을 해결한다.
- 모델은 사용자 선호에 따라 6.1 Sol만 사용한다. Terra·Luna로 전환하지 않는다.
- 데이터 접근·외부 연동·push·배포는 프로젝트 정책과 사용자가 허용한 범위를 따른다.
- 외부 자료의 출처·버전·사용 범위를 기록하고 민감한 정보는 노출하지 않는다.
- 실행한 검증, 사용자 확인, 미검증 부분을 구분해 기록한다.

## 시간 (작업 구간 대비 기본 배분)

| 15% | 23% | 45% | 80% | 85% | 종료 10분 전 |
|---|---|---|---|---|---|
| 인터뷰 끝 | 합의 확정 | E2E v0 | 기능 동결 | WRAP 시작 | 마무리 |

`bash .agents/setup.sh 10:00 240` → 종료 14:00, 마무리 13:50. 같은 날 23:59 이내의 작업 구간을 설정하고 필요하면 종료 상한을 지정한다. 자동 알림은 없다. 일정 수정은 `setup.sh --refresh-times`로 시각만 갱신한다. 늦어지면 사용자와 선택 기능·일정을 조정하고 변경을 기록한다.

## 모델·effort (모두 6.1 Sol)

| 작업 | 권장 effort |
|---|---|
| SETUP · DISCOVER | medium |
| AGREE 핵심 결정·최소 설계 | high |
| BUILD 상세 설계 | high, 재작업 위험이 큰 미해결 결정만 xhigh |
| BUILD 구현·디버깅·검증 설계·독립 리뷰 | high |
| WRAP 코드 이해·심화 문답·피드백 | high |
| 확정 내용 정리·단순 반복 수정·기존 검사 실행과 기록·마무리 확인 | medium |

AGREE 설계를 BUILD에서 반복하지 않는다. xhigh는 핵심 쟁점 검토 뒤 high로 복귀한다. 단계 전환 때 실제 모델·effort를 지원 UI에서 확인하고 STATE에 기록한다. 자동 전환이 아니다. 상세 기준은 AGENTS.md 참조.

## 인터뷰 사다리 — "맥사우수 관제성확"

SETUP: **README의 REQ·산출물 → 필요한 입력·규칙 → 실제 데이터 → 정보 공백(GAP)**을 INTERVIEW에 대조한다. 파일·참조 정보 부재 / 값 누락 / 의미·규칙 미정 / 표본에 없는 경계 사례를 구분한다.

DISCOVER: 필수 산출물·결과 검증을 막는 GAP부터 **관찰 근거 → 반례 → 업무 처리·필요 자료 → 구현 영향**으로 1~2개 질문한다. 사용자가 현업 담당자 또는 담당자 역할의 에이전트와 직접 Q&A하고, Codex는 답을 데이터·README와 재대조한다. 자료는 실제 확보 후 확인 완료로 처리한다. 규칙은 입력 → 기대 결과로 되읽고, GAP ID를 합의·결정·테스트에 연결한다. 미확인·충돌·사용자 가정을 구분한다.

맥락 → 최근 사례 → 우회 방법 → 수치(출처까지) → 관계자 → 제약 → 성공의 모습 → 되읽기 확인

- 질문은 내 말로 직접 쓴다. 해결책 이야기는 문제를 다 들은 뒤에.
- 지름길 질문("할 일 정리해 주세요")은 하지 않는다. 맥락을 짧게 확인하고 중요한 GAP부터 묻는다. 사다리를 순서대로 소진하지 않는다.
- 숫자는 출처를 묻고 데이터와 대조한다.
- 답은 `docs/INTERVIEW.md`에 모아 붙인다. 일반 맥락은 2~3개씩 묶어 분석하고, 구현을 막는 자료·규칙·충돌에 대한 답은 즉시 대조한다.

## 합의문 7칸

필수 요구사항·산출물 파일명은 개수 제한 없이 추적한다. 추가 SC는 3개 이내 권장이다. 필수조건을 변경하면 사용자와 합의하고 이력을 남긴다.

문제 진술 · 원인 · 성공 기준(지표 / 현재 / 목표 / 측정) · 만들 것 · 제외할 선택 기능 · 제약 · 데모 시나리오

→ 5줄 확인 메시지 → 정정 반영 → 변경 이력에 기록

## 검증 7단계

최적화·ML이 있으면 아래 알고리즘 선택·평가 기준도 적용한다.

완료 조건 → 자동 검사 → 실제 실행(브라우저·API 테스트 / 사용자 수동 확인 / 골든 테스트) → 경계 사례 2개 → 필수조건·SC 추적표 → 범위 점검(`git diff --stat`) → 3줄 보고와 로컬 커밋

기준 수치와 다르면 코드를 맞추지 말고 차이를 규칙별로 분해한다. AI가 틀린 지점은 DECISIONS.md에 한 줄씩 남긴다.

## CSV 기반 최적화·ML 선택

CSV·환경 확인 → 목적·제약 또는 타깃·예측 시점·평가 정의 → 라이브러리 / 맞춤 확장 / 직접 구현 비교 → 단순 기준 방법 → 동일 조건 검증. 기본 후보는 요구사항을 충족하는 라이브러리 + 업무 로직이다. 직접 구현은 구체적 이점·지원 공백과 검증 계획으로 정당화한다. DECISIONS에 선택 근거, VERIFICATION에 데이터·버전·설정·실행 결과를 남긴다.

- 최적화: 제약·목적값을 독립 검사하고 실행 가능 해·최적해·시간 초과·불가능 판정을 구분한다.
- ML: 예측 시점과 시간/그룹 분할을 정하고 학습 분할에서만 전처리를 fit한다. 기준 모델과 비교하고 최종 테스트로 튜닝하지 않는다.
- effort: CSV·환경 조사 medium → 목적·평가 확인/방식 비교 high → 복잡한 미해결 설계만 xhigh → 구현·테스트 high → 확정 실험 실행 medium → 해석·리뷰·문답 high. 추론 effort는 학습·탐색 예산과 별개다.
- 상세: `.agents/skills/design-agreement/references/algorithm-selection.md`.

## 이해 점검과 답변 틀

코드 리뷰·온보딩·인수인계에서 설계와 구현을 설명할 수 있도록 문답 자료를 만든다.

WRAP 기본 산출물: `docs/SELF_QUIZ.md`에 최대 6개의 **심화 질문 + 모범답안 + 코드 근거 + 꼬리질문과 답안 요점**. 설계·의사결정·데이터 모델을 우선하고 트랜잭션·동시성·쿼리 성능·전제 오류를 실제 구현에 맞춰 다룬다. 답변을 기다리지 않고 문답 자료부터 완성하며, 시간이 부족하면 질문 수를 줄이고 답안은 유지한다. 한 문제씩 풀기는 선택이다.

읽기 → 쓰기 → 사실 확인. 전제가 실제와 다르면 먼저 바로잡는다: "질문은 ~라고 했지만 실제로는 ~"

최소 한 문항은 **부족 정보 → 데이터만으로 알 수 없던 이유 → 담당자 질문·답 → 결정·구현·테스트 영향**을 설명한다. GAP·REQ·Q&A·코드·실행 증거를 연결하고, 답이 없으면 미확인·사용자 가정으로 표시한다. 문항을 줄여도 이 관점을 유지한다.

① 결론 → ② 위치(파일 · 함수 · 결정) → ③ 근거(버린 대안, 숫자) → ④ 파급과 위험 → ⑤ 다음 조치

최적화·ML이 있으면 총 6문항 안에서 관련이 낮은 문항을 교체해 라이브러리/직접 구현 선택과 알고리즘 보장·평가 한계를 다룬다. 모범답안은 실제 결정·코드·실험에 근거하고, 꼬리질문 답도 포함한다.

## 마무리 확인

필수 산출물·저장 상태 → 검증 결과·알려진 한계 → 실행 방법 → 커밋·남은 변경 → 다음 작업·담당자 확인. 원격 반영이나 배포가 작업 범위에 있으면 그 결과도 별도로 확인한다.

## 명령이 안 될 때

- `/skills`·`$이름`이 안 되면: "AGENTS.md와 .agents/skills/<이름>/SKILL.md를 읽고 따라"
- `/new`가 없으면 Codex를 종료했다가 다시 연다.
- `/review`가 없거나 비거나 모델·effort를 확인할 수 없으면 Codex의 새 세션에서 6.1 Sol / high를 확인하고 `.agents/skills/verify-loop/references/review-prompt.md`를 준다.

## 최소 시작 프롬프트

키트를 설치하지 않고도 아래 요청으로 작업 흐름을 시작할 수 있다. 기존 지침은 보존하고 프로젝트 정책을 따른다.

```
현재 적용되는 지침과 프로젝트 README·요구사항을 읽어.
1) SETUP→DISCOVER→AGREE→BUILD→WRAP으로 진행하고 현재 단계·일정을 docs/STATE.md에 기록해.
2) REQ·산출물과 실제 데이터를 대조해 누락 자료·규칙·경계 사례를 GAP으로 기록해. 담당자에게 물을 질문을 근거·반례와 함께 1~2개 제안하고 답을 입력→기대 결과로 확인해. 담당자가 없으면 내가 확인 주체야.
3) 핵심 범위·데이터 모델·구조·보안 결정은 대안과 영향을 설명하고 내 결정을 기록해. 합의한 구현 세부는 진행해.
4) REQ·SC와 GAP을 합의·결정·코드·검증에 연결하고 미확인·사용자 가정을 구분해.
5) 실행하지 않은 검증은 통과라 말하지 말고 명령·결과·수동 확인을 docs/VERIFICATION.md에 구분해 기록해.
6) 작업마다 무엇/왜/어디서 깨질 수 있는지 보고하고 커밋해. 단계 전환 때 docs/HANDOFF.md를 갱신해.
7) 합의한 작업 시간에 맞춰 체크포인트를 관리하고 종료 10분 전에는 마무리해. 일정·범위 변경은 기록해.
8) WRAP에서 설계·의사결정·DB 심화 질문과 모범답안·근거·꼬리질문 답을 docs/SELF_QUIZ.md에 먼저 완성해. 최소 한 문항은 데이터 공백을 담당자 Q&A로 확인해 구현·검증에 반영한 과정을 다뤄.
9) 모델은 6.1 Sol만 사용해. SETUP·DISCOVER medium, AGREE·BUILD 설계/구현/검증/리뷰 high, 복잡한 미해결 설계 결정만 xhigh, WRAP 심화 문답 high, 단순 정리·마무리 확인 medium을 권장해. 실제 설정을 확인하고 기록해.
```
