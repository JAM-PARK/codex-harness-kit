# Handoff

인수인계 문서는 두 가지 일을 한다. 새 세션이 맥락을 잃지 않고 이어가게 하고, 마감 뒤 결과물에 대한 질문에 사용자가 AI 없이 답할 수 있게 한다.

**권장 모델·effort:** 6.1 Sol만 사용한다. 세션 교대·인수인계 문서 정리·제출 체크는 medium, 코드 이해와 심화 self-quiz·모범답안·피드백은 high. 다음 세션에는 `AGENTS.md`의 해당 작업 권장값을 전달한다.

**적용 경계:** 이 스킬의 이해 점검·피드백은 제출물 확정 전 연습에만 사용한다. 실제 후속 서술형 문제의 해석·답안 작성·검토에는 AI를 사용하지 않는다. 제출물 확정 후에는 에이전트 작업을 종료하며, 사용자 혼자 답변하고 완료 화면을 확인한다.

## 모드 A — 세션 교대

언제: AGREE 완료 직후, E2E v0 완료 직후, 기능 동결 직후, 또는 대화가 길어져 응답 품질이 떨어질 때.

긴 대화를 계속 압축하며 버티는 것보다 정해진 시점에 끊고 문서로 넘기는 편이 정확하고 비용도 적다.

1. `assets/HANDOFF.md`를 바탕으로 `docs/HANDOFF.md`를 갱신한다. 다른 문서에 이미 있는 내용은 반복하지 말고 경로만 적는다.
2. '다음 세션 첫 지시문'을 3줄 이내로 쓴다.
3. `docs/STATE.md`를 갱신하고 커밋한다 (`docs: handoff — <단계>`).
4. 사용자에게 제공 Codex 안에서 새 세션(`/new`, 없으면 Codex 재시작)을 열고 `/status`·`/model`로 6.1 Sol과 다음 작업의 권장 effort를 확인한 뒤 이렇게 시작하라고 안내한다: "AGENTS.md와 docs/HANDOFF.md를 읽고 '다음 세션 첫 지시문'부터 이어가." 도구 업데이트나 관리 설정 변경은 하지 않는다.

## 모드 B — 마감 (작업 시간의 마지막 15%, 85% 시점부터)

1. 구현과 리뷰 반영을 멈춘다. 남은 작업은 '다음 단계 제안'으로 옮긴다.
2. `docs/HANDOFF.md`를 최종본으로 완성한다. 독자는 담당자 팀에서 이 도구를 이어받을 엔지니어다. 실행 방법은 복사해서 바로 돌릴 수 있게 쓴다.
3. **제출 전 연습**: `references/self-quiz.md`를 읽고 설계·의사결정·데이터베이스 중심의 심화 질문을 최대 6개 만든다. 기본으로 모든 문항에 모범답안·코드 근거·꼬리질문과 답안 요점을 붙여 `docs/SELF_QUIZ.md`에 저장하고 HANDOFF에서 연결한다. 사용자 답변을 기다리지 않고 문답 자료를 먼저 완성한다. 남은 시간이 부족하면 문항 수를 줄이되 각 문항의 모범답안은 생략하지 않는다. 사용자가 원하면 한 문제씩 풀고 피드백받는 연습을 진행한다. 실제 후속 서술형 문항을 가져와 연습으로 취급하지 않는다.
4. 공식 과제 문서가 정한 필수 파일명·경로·내용과 모든 REQ / SC의 검증 결과를 확인한다. 실행 방법은 지정된 위치(없으면 `docs/HANDOFF.md`)에 쓴다. 기존 요구사항 문서는 고치지 않는다.
5. 최종 커밋 후 `git status`로 커밋되지 않은 변경이 없는지 확인한다.
6. 과제 마감 10분 전에는 아래 수동 제출 절차를 사용자에게 안내한다. 로컬 커밋이나 깨끗한 `git status`는 플랫폼 제출 완료의 증거가 아니다.

## 사용자 수동 제출 절차 (확정 전에 안내)

1. 필수 파일 경로와 에디터의 저장 완료 상태를 확인하고 저장 충돌을 해결한다.
2. 상단 '제출하고 문제풀기'로 미리보기를 연다. 미리보기 중에도 작업 타이머는 흐르며, 수정이 필요하면 닫고 수정한다. 숨김 파일 등이 생략될 수 있어 목록이 제출 파일 전체를 뜻하지 않는다.
3. '제출물 확정하고 문제풀기'를 직접 누른다. 확정 후 파일을 수정할 수 없으며 AI 작업을 종료한다.
4. 문항 준비 후 사용자가 직접 시작한다. 후속 서술형은 총 30분(6문항·문항당 5분)이며 실제 응시 화면과 최신 공지를 따른다. AI·복사 붙여넣기 없이 답하고, 확정한 답안은 되돌릴 수 없다.
5. 마지막 답안 제출 뒤 처리·업로드를 기다린다. 최종 완료 화면에서 제출 ID·시각·파일 수·크기를 확인한 뒤 종료한다. 감독 연결은 완료 안내까지 유지한다. 대기·오류에도 전체 종료 14:00은 연장되지 않으며 장애는 문의 버튼으로 접수한다.
