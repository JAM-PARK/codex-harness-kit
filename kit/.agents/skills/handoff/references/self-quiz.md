# 이해 점검 질문 만들기

제출물 확정 전 연습 전용이다. 실제 후속 서술형에서는 AI 사용이 금지되므로 문항 해석·답안 생성·첨삭을 하지 않는다. 남은 과제 시간에서 제출 준비 시간을 먼저 확보하고, 시간이 부족하면 연습 질문 수를 줄인다.

사용자가 만든 결과물에 대해, 사용자가 AI 없이 답해야 할 연습 질문을 최대 6개 만든다. 이 저장소의 실제 코드·커밋·문서에 근거한 구체적 질문이어야 한다. 일반론 질문은 만들지 않는다.

## 질문 유형 (각 1개)

1. **구조의 이유**: "X를 Y 방식으로 만든 이유와 버린 대안은?"
2. **장애 대응**: "Z가 실패하면(입력 이상, 외부 API 실패 등) 무슨 일이 생기고 어떻게 대응하나?"
3. **데이터 경계**: "입력에 A 같은 경우가 섞이면 결과가 어떻게 되나?"
4. **확장 · 운영**: "사용자나 데이터가 10배가 되면 어디가 먼저 문제가 되나?"
5. **약점 인정**: "지금 가장 불안한 부분은 어디이고 다음에 무엇을 하겠나?"
6. **전제 오류**: 담당자 요청, AI 제안, 핵심 결정 중 하나를 일부러 사실과 다르게 깐 질문. 예: 실제로는 중복을 제거했는데 "중복을 제거하지 않은 이유는?" 사용자는 전제부터 바로잡아야 한다.

## 답변 틀 (사용자에게 먼저 안내)

① **결론**: 한 문장. 전제가 틀렸으면 "질문은 ~라고 했지만 실제로는 ~"로 시작
② **위치**: 어느 파일 · 함수 · 결정인지 구체적으로 짚는다
③ **근거**: 버린 대안, 담당자 확인, 테스트 결과, 숫자
④ **파급**: 왜 문제가 되는지, 영향이 어디까지 가는지
⑤ **다음 조치**: 무엇을 검증하거나 고칠지

## 진행

- 한 번에 한 문제씩 낸다. 사용자는 제한 시간(예: 3~5분)을 정해 두고 AI 없이 직접 타이핑한다.
- 답을 받은 뒤 코드와 대조해 ①~⑤ 각각 충분 / 부족을 짧게 피드백한다. 전제 오류 문항은 바로잡았는지부터 본다.
- 사용자가 설명하지 못한 부분은 해당 코드를 함께 읽고 핵심을 3줄로 정리해 준다.
