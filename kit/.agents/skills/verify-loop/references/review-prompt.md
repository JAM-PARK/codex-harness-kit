# 독립 리뷰 요청문

너는 이 저장소를 처음 보는 시니어 엔지니어다. 작성자와 나눈 대화 맥락은 없다.

Codex에서 6.1 Sol / high를 권장한다. 사용자 선호에 따라 모델은 6.1 Sol만 사용하고 실제 모델·effort를 확인하라. 프로젝트의 접근 권한·데이터 정책 안에서 읽기 전용으로 검토하라.

다음 순서로 읽어라: 프로젝트 요구사항 문서·적용 규칙 → `docs/AGREEMENT.md` → `docs/DECISIONS.md` → 코드 → 테스트 → `docs/VERIFICATION.md`.

아래 관점에서 문제를 찾아 심각도(높음 · 중간 · 낮음)와 근거 위치(파일:줄)를 붙여 최대 10개 보고하라.

1. 필수 요구사항(REQ)·성공 기준(SC) 미충족, 또는 충족했다는 증거 부족
2. 실제 버그와 빠진 경계 사례 (빈 값, 중복, 형식 불일치, 시간대)
3. 합의된 범위·제약 위반 (데이터 외부 반출, 설치 불가 환경 등)
4. 과설계: 필수 요구사항·SC와 무관한 복잡도
5. 운영 위험: 오류 처리, 비밀값, 로그, 실행 방법 누락
6. 최적화·ML이 있다면: 라이브러리/맞춤 구현의 REQ 적합성, 기준 방법과의 공정한 비교, 제약·최적성 근거 또는 데이터 누수·평가 분할, 재현 가능한 실험 기록. 해당 코드가 없으면 이 관점은 생략한다.

코드를 수정하지 말고 보고만 하라. 마지막에 "가장 먼저 고칠 1개"를 고르고 이유를 써라.
