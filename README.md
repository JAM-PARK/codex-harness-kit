# codex-harness-kit

[Codex CLI](https://github.com/openai/codex)에서 쓰는 작업 하네스입니다. 담당자 인터뷰 → 합의 → 얇은 E2E → 검증 → 인수인계 흐름과 시간 체크포인트를 `AGENTS.md`와 Agent Skills 4개로 고정합니다.

이 배포본은 Cofa Probe 대회 환경용입니다. 운영 공지·과제 필수조건이 하네스보다 우선하며, 가이드와 메일이 충돌하면 최신 메일을 따릅니다. 제공 Codex를 업데이트하지 않습니다. 이 공개 키트의 사전 유지보수·push와, 응시 중 작업 공간에서 금지되는 외부 전송·push를 구분하세요.

## 구성

```
kit/
├── AGENTS.md              운영 규칙 (Codex가 작업 공간 루트에서 자동으로 읽음)
└── .agents/
    ├── setup.sh           체크포인트 계산, docs/STATE.md 생성
    ├── CHEATSHEET.md      1장 요약
    └── skills/
        ├── discovery-interview/   담당자 인터뷰
        ├── design-agreement/      합의문 · 최소 설계 · 작업 분해
        ├── verify-loop/           작업 단위 검증과 독립 리뷰
        └── handoff/               인수인계와 이해 점검
```

## 설치 (제공 환경의 작업 공간 루트에서)

플랫폼 안의 Codex에 아래 설치를 요청하세요. Bash와 Python 3가 필요합니다. 개인 PC 파일을 업로드하거나 외부 브라우저로 접근하지 않습니다. clone만으로 `kit/` 아래 지침이 작업 루트에 적용되지는 않습니다.

```bash
kit_source=$(mktemp -d) &&
git clone --depth 1 https://github.com/JAM-PARK/codex-harness-kit "$kit_source" &&
python3 "$kit_source/install.py" "$PWD" &&
bash .agents/setup.sh 10:00 180             # 실제 과제 시작 시각으로 바꾸기
```

- 설치기는 기존 프로젝트 지침을 보존하고 표시된 하네스 블록을 한 번만 추가합니다. 동일 파일은 건너뛰며, 내용이 다른 스킬·구버전 하네스·`AGENTS.override.md` 등 충돌이 있으면 파일을 복사하기 전에 중단합니다. 기존 파일을 삭제해 우회하지 말고 지침과 차이를 검토해 직접 병합하세요.
- 설치 후 제공 Codex를 작업 루트에서 새로 시작하고 `/status`·`/model`·`/skills`를 확인합니다. 모델은 **6.1 Sol만 사용**합니다. 사용자 선호에 따라 Terra·Luna를 제외하며, Astra·개인 API 키·별도 AI 연결도 사용하지 않습니다. 리뷰·새 세션에도 같은 제한이 적용됩니다.
- 첫 요청: "현재 적용된 지침 파일 경로와 스킬 4개를 나열하고, 기존 규칙과 하네스의 충돌을 보고해. 공식 운영 공지와 과제 필수조건을 우선해." 상위·하위 폴더 지침과 `AGENTS.override.md`에 의해 적용 내용이 달라질 수 있으므로 관리 설정은 바꾸지 않습니다.
- 스킬은 `/skills`로 보거나 `$discovery-interview`처럼 부릅니다. 잡히지 않으면 "AGENTS.md와 .agents/skills/<이름>/SKILL.md를 읽고 따라"라고 요청합니다.
- 사용한 공개 저장소 URL·커밋·활용 범위를 `docs/HANDOFF.md`에 기록합니다. 이 저장소와 활용하는 저장소는 2차 예선 결과 통지 전까지 공개 상태여야 합니다. 외부 자료로 결과물을 통째로 대체하지 않습니다.

## 시간 설정과 복구

`setup.sh [--refresh-times] <시작 HH:MM> <작업 분> [과제 마감 상한 HH:MM]`은 같은 날의 시각과 1~180분의 작업 시간으로 체크포인트를 계산합니다. **플랫폼 타이머가 최종 기준이며 자동 알림 기능은 없습니다.**

- 실제 과제 시작이 10:00이면 `10:00 180` → 과제 마감 13:00, 제출 준비 12:50입니다. 설치를 끝낸 시각이 아니라 과제 시작 버튼을 누른 시각을 넣습니다.
- 전체 종료 14:00은 코딩 마감이 아닙니다. 후속 서술형 30분과 준비 대기 시간을 별도로 남겨야 합니다. 늦게 시작했다면 그 시간을 남긴 과제 마감 상한을 정하세요. 예를 들어 `10:30 180 13:20`은 작업을 170분으로 줄이고 전체 종료까지 40분을 남깁니다. 이는 운영상 여유를 둔 예시이며 문항 준비 지연까지 보장하지 않습니다.
- 잘못된 입력은 파일 생성 전에 실패합니다. 기존 STATE의 일정이 같으면 보존하고, 다르거나 구버전의 `HH:MM`이 남아 있으면 중단합니다. 플랫폼 시각 확인 후 `bash .agents/setup.sh --refresh-times 10:00 180`처럼 실행하면 **작업 시간·체크포인트 두 항목만** 갱신하고 단계·기록은 보존합니다. 현재 단계와 다음 체크포인트는 별도로 확인하세요.
- 10분 이하의 짧은 일정은 실제 시각을 기록하고 즉시 제출 준비를 안내합니다. STATE를 새로 만들 때는 WRAP으로 시작합니다.

## 응시 중 경계와 제출

- 문제·파일·결과물의 외부 전송·공유·push는 사용자 승인으로도 허용되지 않습니다. 공개 자료를 가져오는 clone·다운로드와 구분합니다.
- Computer Use·브라우저 자동 조작을 사용하지 않습니다. Codex는 로컬 서비스의 CLI·curl·테스트를 실행하고, 사용자는 플랫폼 Browser에서 직접 UI를 확인합니다.
- 이해 점검은 제출물 확정 전 연습입니다. 실제 후속 서술형에서는 AI·복사 붙여넣기를 사용하지 않습니다.
- 사용자 수동 절차: 필수 파일·저장 상태 확인 → 제출 미리보기 → 제출물 확정 → AI 작업 종료 → 직접 서술형 응시 → 최종 완료 화면의 제출 ID·시각·파일 수·크기 확인. 로컬 커밋은 플랫폼 제출을 대신하지 않습니다.
- 응시 준비는 최신 메일 기준으로 Chrome, 09:40 접속 및 추가 공지 확인, 유선 외장 키보드·마우스 또는 노트북 내장 입력장치, 충전·휴대폰 Wi-Fi·감독 연결을 확인합니다. 장애는 발생 시각·증상을 플랫폼 문의 버튼으로 접수합니다.

## SETUP·DISCOVER: 데이터 분석에서 담당자 Q&A까지

과제에 제공된 **현업 담당자 에이전트**에게 사용자가 직접 질문하고, Codex가 데이터 분석·질문 제안·답변 대조를 맡습니다. SETUP부터 discovery-interview 스킬을 사용합니다.

1. README의 요구사항·산출물마다 필요한 입력·업무 규칙을 적고 실제 파일·컬럼·관계와 대조합니다.
2. 빠진 파일·참조 자료, 누락 값, 불명확한 의미·규칙, 표본에 없는 엣지 케이스를 `docs/INTERVIEW.md`에 GAP ID로 기록합니다.
3. 필수 산출물을 막거나 결과를 바꾸는 GAP부터 관찰 근거·구체적 반례를 붙여 한 번에 1~2개 질문합니다. '더 알아야 할 것이 있나요?' 같은 포괄적 질문으로 대신하지 않습니다.
4. 담당자 답을 **입력 → 기대 결과**로 되읽고 데이터·README와 재대조합니다. 추가 자료는 실제 확보·스키마 확인 후 해결로 처리하며, 모호함·충돌은 후속 질문으로 확인합니다.
5. 확인한 정보는 같은 GAP ID로 합의문·설계 결정·경계 사례 테스트에 연결합니다. 미응답·자료 대기·사용자 가정은 확인 완료와 구분하고, 자료 부재를 가짜 값으로 채우지 않습니다.

예를 들어 '같은 ID의 여러 행'을 발견하면 중복 제거부터 구현하지 않습니다. 이력인지 별개 사건인지, 대표 행 기준과 같은 시각일 때 처리까지 담당자에게 확인한 뒤 키·집계·테스트에 반영합니다. 상세 절차는 [데이터 공백 확인 가이드](kit/.agents/skills/discovery-interview/references/data-gaps.md)에 있습니다. 기존 15% 인터뷰 체크포인트 안에서 중요한 공백을 우선하며, 미해결 항목은 영향과 다음 조치를 남겨 이후 단계로 넘깁니다.

## 단계별 모델·effort 권장

모든 단계에서 **6.1 Sol**을 사용합니다. 아래는 시간 제한과 재작업 위험을 고려한 키트 권장안이며, 단계별 성능을 측정해 보장한 값은 아닙니다. [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-6.1-sol)는 medium을 기본값으로 안내하며 medium·high·xhigh를 지원합니다. 제공 환경에서 실제 선택 가능한 값은 직접 확인하세요.

| 단계 · 작업 | 권장 effort |
|---|---|
| SETUP · DISCOVER | medium |
| AGREE — 성공 기준·최소 설계·핵심 결정 | high |
| BUILD — 상세 설계 | high, 재작업 위험이 큰 미해결 결정만 xhigh |
| BUILD — 구현·디버깅·검증 설계·독립 리뷰 | high |
| WRAP — 코드 이해·심화 self-quiz·모범답안 | high |
| 확정 내용 정리·단순 반복 수정·기존 검사 실행과 기록·제출 체크 | medium |

실전에서 사용한 'BUILD 전까지 medium / BUILD 설계 xhigh / 구현 high'를 기준으로 **AGREE의 핵심 결정은 high로 올리고, BUILD 설계는 high를 기본으로 권장합니다.** 합의 단계의 오류로 인한 재작업을 줄이고, xhigh는 복잡한 데이터 불변식·트랜잭션·스키마 결정에 한정하려는 배분입니다. DB가 있다는 이유만으로 xhigh를 쓰지는 않습니다. AGREE에서 확정한 최소 설계를 BUILD에서 되풀이하지 않습니다. 상세 전환 기준은 [운영 규칙](kit/AGENTS.md#단계별-권장-effort-모델은-모두-61-sol)에 있습니다.

이 지침은 모델 설정을 자동으로 바꾸지 않습니다. 단계 전환 시 제공 Codex의 지원 UI에서 실제 모델·effort를 확인하고 STATE에 기록합니다. 시간 부족 시 선택 기능·검토 범위를 줄이며 Terra·Luna로 전환하지 않습니다.

## WRAP 이해 점검

기본 결과물은 `docs/SELF_QUIZ.md`의 **심화 질문 + 문항별 모범답안 + 코드 근거 + 꼬리질문과 답안 요점**입니다. 사용자 답변을 기다리지 않고 먼저 완성합니다. 설계·의사결정·데이터베이스를 중심으로 최대 6문항을 만들고, 시간이 부족하면 핵심 문항 수를 줄이되 모범답안은 유지합니다.

실제 코드·스키마·결정·테스트를 근거로 대안의 손익, 데이터 무결성, 트랜잭션·동시성, 쿼리 성능과 장애 시 동작을 설명하게 합니다. DB가 없으면 현재 저장 방식의 한계와 DB 전환 조건을 다루고, 구현하지 않은 보장을 지어내지 않습니다. 사용자가 원하면 한 문제씩 풀고 피드백받는 방식으로도 연습할 수 있습니다. 제출물 확정 전 연습에만 사용합니다.

최소 한 문항은 **어떤 정보가 부족했는지 → 왜 데이터만으로 알 수 없었는지 → 담당자에게 어떻게 확인했는지 → 답이 설계·구현·테스트를 어떻게 바꿨는지**를 다룹니다. 모범답안은 실제 GAP·Q&A와 코드·검증 증거를 연결하고, 답을 못 받은 부분은 미확인·가정으로 설명합니다. 문항 수를 줄여도 이 관점은 유지합니다.

## 키트 유지보수 검증

```bash
python3 -m unittest discover -s tests -v
bash -n kit/.agents/setup.sh
```

로컬 검증은 Cofa 제공 버전의 실제 지침·스킬 로딩을 보장하지 않습니다. 1회·15분 사전 체험에서 제공 버전을 유지한 채 인식 여부와 수동 미리보기를 확인하세요.
